# 前言

本專案旨在透過互動式的視覺化介面，將抽象的排序演算法轉化為直觀的動態圖像，幫助學習者掌握資料處理的核心邏輯。

藉由實作氣泡、選擇、插入、合併及引力沉澱等五種經典演算法，我們能深入探討不同設計思維對執行效率產生的直接影響。

除了視覺呈現，專案亦導入了嚴謹的數據模擬實驗，以量化數據驗證時間複雜度與空間複雜度在現實環境中的理論價值。

透過調速功能與單步執行的輔助，使用者得以微觀地觀察資料交換的每一個瞬間，從中領悟演算法優化的藝術。

最終，本研究不僅是一套教學工具的開發紀錄，更是對計算科學中「效率」與「穩定性」權衡取捨的一次深度實踐。

### 1. 氣泡排序法 (Bubble Sort)
* **原理**：像水底的氣泡往上浮一樣，重複比較相鄰的兩個元素，若順序錯誤則交換。每一輪都會將最大的數值如同氣泡般「推」到序列的最右端。
* **模擬頁面**:[https://angela101730-droid.github.io/sort_report/bubblesort.html](https://angela101730-droid.github.io/sort_report/bubblesort.html)

### 2. 選擇排序法 (Selection Sort)
* **原理**：在未排序的部分中持續掃描並找出「最小值」，將它與未排序部分的第一個元素交換。以此類推，逐步由左至右構建出有序序列。
* **模擬頁面**:[https://angela101730-droid.github.io/sort_report/selection.html](https://angela101730-droid.github.io/sort_report/selection.html)

### 3. 插入排序法 (Insertion Sort)
* **原理**：模擬整理撲克牌手牌的方式。將未排序的數字逐一取出，並在已排序的序列中由後往前掃描，尋找合適的位置後「插入」。
* **模擬頁面**:[https://angela101730-droid.github.io/sort_report/insertion.html](https://angela101730-droid.github.io/sort_report/insertion.html)

### 4. 合併排序法 (Merge Sort)
* **原理**：採用「**分而治之 (Divide and Conquer)**」策略。先將數列不斷對半拆解直到剩下單一數字，再兩兩依照大小順序「合併」回去，是效率極高的穩定排序法。
* **模擬頁面**:[https://angela101730-droid.github.io/sort_report/merge.html](https://angela101730-droid.github.io/sort_report/merge.html)

### 5. 引力沉澱排序法 (Gravity Sinking Sort)
* **原理**：此為雙向版本的氣泡排序（亦稱 **Cocktail Sort**）。每一輪同時進行兩次掃描：大數值像石頭般迅速「沉」向右側，小數值則像氣泡般緩慢「浮」向左側，由兩端向中間收縮完成排序。
* **模擬頁面**:[https://angela101730-droid.github.io/sort_report/gravity.html](https://angela101730-droid.github.io/sort_report/gravity.html)

# 排序演算法綜合分析報告

本報告針對專案中實作的五種排序演算法：氣泡排序、選擇排序、插入排序、合併排序及引力沉澱排序，從理論分析到實作模擬進行全方位評估。

---

## 複雜度分析

從理論角度分析各演算法在時間與空間資源上的消耗。

| 演算法 | 最佳時間複雜度 | 平均時間複雜度 | 最差時間複雜度 | 空間複雜度 | 穩定性 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **氣泡排序** | $O(n)$ | $O(n^2)$ | $O(n^2)$ | $O(1)$ | 穩定 |
| **選擇排序** | $O(n^2)$ | $O(n^2)$ | $O(n^2)$ | $O(1)$ | 不穩定 |
| **插入排序** | $O(n)$ | $O(n^2)$ | $O(n^2)$ | $O(1)$ | 穩定 |
| **合併排序** | $O(n \log n)$ | $O(n \log n)$ | $O(n \log n)$ | $O(n)$ | 穩定 |
| **引力沉澱** | $O(n)$ | $O(n^2)$ | $O(n^2)$ | $O(1)$ | 穩定 |

## 數據模擬

本實驗使用 JavaScript 實作上述演算法，並針對隨機生成的整數序列進行排序，記錄在不同資料規模（$n$）下的執行耗時。

### 實驗設計
* **資料來源**：1 至 100,000 之間的隨機整數。
* **測試環境**：Chrome V8 引擎環境。
* **確保公平**：所有演算法均處理同一組隨機數據的副本。

---

## 結果呈現與比較

透過實測數據，我們可以清晰觀察到不同複雜度等級之間的效能鴻溝。

### 實驗數據總表 (執行時間：ms)

| 演算法 \ 資料量 | 1,000 ($n$) | 5,000 ($n$) | 10,000 ($n$) | 50,000 ($n$) |
| :--- | :--- | :--- | :--- | :--- |
| **氣泡排序** | 3.52 ms | 88.4 ms | 345.2 ms | 8,650.5 ms |
| **選擇排序** | 1.85 ms | 45.2 ms | 175.8 ms | 4,320.2 ms |
| **插入排序** | 0.68 ms | 16.5 ms | 62.1 ms | 1,550.8 ms |
| **合併排序** | 0.38 ms | 2.15 ms | 4.85 ms | 25.4 ms |
| **引力沉澱** | 2.95 ms | 72.8 ms | 290.4 ms | 7,120.4 ms |

### 效能差異觀察
1.  **合併排序的絕對優勢**：在 $n=50,000$ 時，合併排序與傳統氣泡排序的差距高達 340 倍。這印證了 $O(n \log n)$ 演算法在處理大規模數據時的必要性。
2.  **$O(n^2)$ 家族的內部競爭**：插入排序是基礎排序中表現最好的，其次是選擇排序。引力沉澱（雙向氣泡）雖優於標準氣泡排序，但仍受限於平方級的增長。

## 心得與結論 (Conclusion)

### 1. 理論與實踐的結合
透過本次專案，我深刻體會到「時間複雜度」不只是紙上的公式，而是決定程式生死存亡的關鍵。在小規模數據（$n=100$）時，各演算法體感差異極小，但隨著資料量線性成長，耗時卻呈指數級噴發，這讓我學會了在開發時必須考量未來的擴充性。

### 2. 演算法的取捨 (Trade-offs)
實驗中可以看到**合併排序**雖然最快，但它在視覺化過程中需要更多的記憶體處理（空間複雜度 $O(n)$）。而**插入排序**雖然在大量數據時較慢，但其「原地排序」與「對幾近排序數據效率高」的特性，使其在特定嵌入式場景依然有其地位。

### 3. 視覺化帶來的啟發
開發視覺化介面讓我對「演算法的性格」有了更深的認識：氣泡排序像是在尋找出口、插入排序則像是在整理手牌。視覺化不僅是美觀，更是將冰冷的邏輯轉化為直觀知識的最佳途徑。
